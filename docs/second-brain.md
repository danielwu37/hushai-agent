# 第二大脑（hushai brain）设计

> v2，2026-11-17。替换 11-14 的 v1（v1 在对账路径上按段落机械切笔记，11-16 审核判定不可用并回滚）。
> 一句话：**只把显式交给它的材料，由模型编译成一套互相链接、带出处的 Markdown 页面；人读、AI 读、Obsidian 直接打开都行。**

## 1. 借鉴了什么、没借鉴什么

| 来源 | 借鉴 | 在这里的样子 |
| --- | --- | --- |
| 卡帕西 LLM Wiki（2026-04） | 三层：原料（只读）→ 维基（模型维护）→ 规则（schema）；三个动作 ingest / query / lint；`index.md` 目录 + `log.md` 日志；「编译一次、持续维护」而不是每次提问都从原文重新检索 | 原料 = 前缀收件行 + 投放文件；维基 = `hub/projects、notes、people、sources`；规则 = `prompts/brain-ingest.zh.md` + `AGENTS.md` §1.3；动作 = `hushai brain ingest / ask / lint`；目录 `hub/index.md`；日志 `hub/daily/<日期>.md` |
| Obsidian | 文件名即标题、`[[双链]]`、YAML 属性（frontmatter）、别名、日记页、反向链接与图谱 | 每页 YAML 头（type/title/aliases/domain/tags/summary/status/updated）；正文用 `[[标题]]`；入脑日志按日一页；整个 `hub/` 可直接当 Obsidian 库打开 |
| LifeOS（PAI） | 类型化档案（项目 / 人物 / 主题）；定期「重温」；体检自愈 | 三种页面类型 + 来源页；晨间简报「重温」一页旧页；`lint` 进 `doctor` |
| 不借鉴 | 向量库、数据库、常驻进程、整套 LifeOS、模型自由改全库 | 一切是 Markdown + 定时器；模型只能返回 JSON，增改由代码落盘 |

## 2. 三层与目录

```text
hub/
├── inbox/*.md                 ← 原料①：「做了什么」以 笔记：/来源：/人物：/项目：/入脑： 开头的收件行
├── exchange/in/入脑/           ← 原料②：投放文件夹（.md/.txt，≤64 KB，只读，按哈希记账）
├── exchange/in/<端>/入脑-*.md  ← 原料②：各端经闸门 put-exchange 存的文件，文件名以「入脑-」开头即可
├── index.md                   ← 目录：按类型分节，每页一行 [[标题]]｜一句话｜领域｜更新日；≤200 行（代码生成）
├── projects/<标题>.md         ← 项目页（有目标、会结束的事）
├── notes/<标题>.md            ← 主题页（概念、方法、政策、长期关注）
├── people/<标题>.md           ← 人物页（身份、关系、对方说过做过的事；不写评价）
├── sources/来源-<标题>.md      ← 原件摘要页（每份投放文件一页，链到它影响的页面）
└── daily/<日期>.md            ← 入脑日志（每批一行：做了什么、新建/更新了哪些 [[页]]、原料）
```

## 3. 页面格式

```markdown
---
type: project
title: 中转住宿政策申请
aliases: [中转住宿]
domain: 工作
tags: [航线, 政策]
summary: 改为 2027 年一季度，人数口径待定
status: 有出处
created: 2026-11-17
updated: 2026-11-18
---

一句话：这是什么、现在怎样。

### 要点
- 申请期改为 2027 年 1–3 月（11-17）
- 测算人数以 11110 为准（11-18 更正，旧说法：10939）

### 待跟进
- 定口径后定稿

## 来源
- 收件 2026-11-17 steward 15:44：项目：中转住宿……
- [[来源-某份原件]]

## 我的笔记
（使用者手写，AI 永远不改）
```

三块归属：

| 块 | 谁写 | 规则 |
| --- | --- | --- |
| YAML 头 | 代码 | 键序固定；`status` 只有「有出处」「已核实」两种，模型不能写「已核实」，只有 `hushai brain verify` 能标；正文一变就退回「有出处」 |
| 正文 | 模型 | 每次编译给出**融合后的完整正文**；旧说法被推翻时写明更正和旧说法 |
| `## 来源` | 代码 | 只增不删，引用收件行（日期、端、时间、原句前 80 字）或来源页 |
| `## 我的笔记` | 使用者 | 代码原样保留；模型看不到 |
| `locked: true` | 使用者 | 整页不再被编译改动（日志里记「已锁定未改」） |

## 4. 三个动作

### 4.1 ingest（编译，调模型）

```text
收集原料（since 之后、未编译、非隔离领域、非 heal 端）
  → 收件行每 15 行一批；每个文件单独一批
  → 每批：本地按标题/别名挑最多 6 页相关旧页 + 目录 → 拼提示词
  → runner.run_model（[jobs] brain，没配借 digest；单独预算 [brain] max_daily_calls）
  → 校验：类型、领域（隔离领域整页丢弃）、标题清洗、每页必须引用至少一条收件行、最多 8 页、去掉模型写的「来源/我的笔记」节
  → 短暂持 runner.lock：增改页面（按标题/别名合并，不重名）→ 写来源页 → 追加日志 → 记账（已编译行号/文件哈希）
  → 释锁后排空期间被挡住的对账事件
→ 全部批次后：重写 index.md、git 提交「brain-ingest <时间>」
```

- **不在对账路径上**：会话结束、同步、Muse 写入都不触发；只由定时器（默认每晚 22:30，避开 21:30 汇总与 :00/:15/:45 同步）或手动运行。
- **单次上限**：`max_calls_per_run`（默认 6 批），剩下的下次再编。
- **失败**：材料原样保留；连续失败（all-failed）写一条 `brain:ingest` 告警，下次成功自动撤下。
- **崩溃重放幂等**：页面按标题合并、来源去重，所以落盘后、记账前崩溃，重跑只会把同一结果再写一遍。

### 4.2 ask（检索，不调模型）

`hushai brain ask "问题"`：中文按相邻两字、英文按词打分（标题/别名 > 标签 > 摘要 > 正文），返回最相关的几页（路径、状态、更新日、命中原句）和它们链出去的相关页。正在对话的 AI 打开原页作答。值得留下的答案写成收件行「笔记：……」，下次编译回填——这就是卡帕西说的「答案也回存进维基」，只是统一走收件这一个写入口。

### 4.3 lint（体检，不调模型）

一遍扫完（O(页数)）：断链、重名（标题/别名/文件名冲突）、头信息不全、缺来源、孤页、久未更新待复核（`stale_days`，默认 90 天，已核实的不算）、目录超行、隔离领域漏进来、投放文件过大、待编译积压。`doctor` 里一行结论：隔离领域漏进来为 FAIL；断链、重名、头信息不全、目录超行为 WARN。

## 5. 接入系统的位置

| 接入点 | 做什么 |
| --- | --- |
| 收件 | 原料入口，各端都能写；不改五段式格式 |
| 闸门（Muse） | `put-exchange --name 入脑-xxx.md` 存的文件会被编译 |
| 定时器 | `hushai-<实例>-brain.{service,timer}`，`hushai brain units --out <目录>` 生成 |
| 晨间简报 | 「第二大脑」一节：昨天以来新入脑的页 + 按日期轮换的一页旧页重温（隔离领域不出现） |
| doctor | `second-brain` 一行体检结论 |
| 预算 | 主预算不数 `brain`（与 `capture` 一样单独计） |
| 同步 | `index.md`、四个页面目录和 `daily/` 已在推送白名单；隔离领域的页不会生成 |
| 菜单 | `hushai config` → 6：开关、参数、立即编译、检索、体检 |

## 6. 配置

```ini
[jobs]
brain = claude:light        ; 不配就借 digest 的链

[brain]
enabled = false             ; hushai brain enable 打开，并把 since 设为当天
time = 22:30                ; 定时器编译时间
since = 2026-11-17          ; 只收此日起的收件行（避免一开就把积压全量编译）
max_daily_calls = 12        ; 单独预算
max_calls_per_run = 6
index_max_lines = 200
stale_days = 90
```

## 7. 命令

| 命令 | 作用 |
| --- | --- |
| `hushai brain enable [--since 日期]` / `disable` | 开关；disable 顺带清配置目录里的 brain 单元并列出系统目录残留 |
| `hushai brain ingest [--force] [--max-calls N] [--since 日期] [--dry-run]` | 编译 |
| `hushai brain ask "问题" [--limit N]` | 检索 |
| `hushai brain lint` / `status` | 体检 / 状态 |
| `hushai brain add <文件或 -> [--name 名字]` | 放进投放文件夹 |
| `hushai brain verify <标题或别名>` | 使用者核实后标「已核实」 |
| `hushai brain units --out <目录>` | 生成定时器单元（只生成不安装） |

## 8. 与 v1 的差别（为什么这次能用）

| v1 的问题（11-16 审核） | v2 |
| --- | --- |
| 扫 `exchange/in/**` 全部，含 legacy 过程档案 | 只收显式前缀行和投放文件夹 / `入脑-` 文件 |
| 按空行机械切「原子笔记」，标题是半截句子 | 模型按实体融合进已有页面，标题清洗、全库唯一 |
| 有出处即标 verified | 「有出处」与「已核实」分开，只有使用者能标核实 |
| `@gmail` 被识别成人物 | 人物由模型按内容判断，提示词禁止评价与人事信息 |
| 两两去重 O(n²)、每次对账都跑、持锁 18 秒 | 不在对账路径；按标题/别名哈希合并 O(n)；模型调用不持 runner.lock |
| 合并后断链 115 条 | 从不删页、不改名；lint 报断链 |
| 健康领域不过滤 | 原料、校验、简报三处按领域隔离 |
| 8 个定时器单元，开关与实际行为不符 | 1 个定时器，`enabled` 一个开关 |
